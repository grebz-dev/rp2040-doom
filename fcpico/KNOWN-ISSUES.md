# Known issues

Current limitations of the FC PICO port. Each entry gives the symptom, when it
applies, and a workaround where one exists.

## Performance

- **Low frame rate with actors on screen.** Converting the background frame
  takes about 38 ms per frame on the RP2350, against a design target of 8 ms.
  In cosimulation the device-timing model gives 13–14.5 fps with native enemy
  and pickup sprites and about 17.7 fps when actors are streamed. These are
  modelled figures; frame rate on hardware has not been measured. The serial
  `video` lines report published and rendered FPS on a running console.
- **Native sprites can lag or flash.** A picture waits until the console shows
  its world sprite generation, so sprite uploads (four tiles per NMI) can hold
  back pictures. Occasional whole-frame flashes or desyncs near the
  native/streamed distance threshold are reduced but not confirmed resolved.
  No long soak run has been done. `FCPICO_WORLD_LOOSE=ON` publishes pictures
  without waiting for sprites, which raises frame rate at the cost of trailing
  sprites.

## Display

- **Picture geometry is unverified.** The 224-line picture displays correctly
  on an NES-001, but exact geometry has not been checked against an
  independent reference.
- **The HUD tints with damage and pickup flashes.** The status bar shares a
  background palette with the game view, so palette flashes affect it too.
- **Native UI symbols once dropped out after power cycles.** In early sprite
  tests, two symbols intermittently disappeared after power cycling. Later
  captures showed all symbols, but the cause was never identified.

## Input, saves and options

- **Controller mapping is incomplete.** Movement, fire, B use/strafe, weapon
  cycling, automap, menus and pause work. Other context-dependent mappings
  are not implemented.
- **Saving and loading have not been validated** on the cartridge.

## Build and assets

- **The device build needs the diagnostic startup profile.** Hardware builds
  without `FCPICO_DIAGNOSTIC_ENGINE_DELAY=ON` (a 30-second startup countdown
  plus bus statistics) failed to start, showing USB descriptor errors and
  `PICO NOT FOUND` on the console. Which part of the profile is required has
  not been isolated. `tools/build_device.sh` always enables it.
- **A plain CMake device build embeds an old console ROM.** Without
  `tools/build_device.sh`, the firmware embeds `bootrom/src/PG_main.asm`
  (`20DOOM-02-0002`). The current ROM is generated by
  `tools/build_world_sprite_rom.py`.
- **Native world sprites need a firmware build from your own IWAD.** The atlas
  identity is compiled into the firmware, so a different WAD needs a rebuild.
  Only shareware sprite families have reviewed palettes. With the shareware
  WAD the atlas uses 408 KB of its 512 KB flash region. Registered or Ultimate
  Doom families would likely exceed it, and Doom II actors are not in the
  scope; actors without atlas entries are streamed. Only the bundled shareware
  `doom1.whx` is wired into the build.
- **`whd_gen` does not build with the host GCC used for development** (an
  error in `src/whd_gen/whd_gen.cpp`). Host engine builds should target
  `doom_tiny_fcpico` (and `host_shim_test`) instead of `all`.
- **Two host engine golden tests are stale.** `engine_host_determinism` and
  `engine_title_menu_golden` compare against frame hashes recorded before the
  native HUD and world sprite changes, and fail. `engine_input_walk` passes.

## Coverage

- **Only tested on an NTSC NES-001.** PAL consoles and the Famicom have not
  been tested.
- **The original RP2040 Doom VGA targets** have not been verified since the
  engine changes. The changes are behind `FCPICO`/`FCPICO_SUPERBUILD`.
- **Cosimulation runs the console only.** MesenCE runs the 6502 and PPU
  against the host cartridge model. It does not emulate the ARM, PIO or bus
  electrical timing, and the full engine-to-console loop runs only from
  recorded host frames.
- **The PIO bus-direction handshake** (`fcppu_r` → `fcppu_dir`) is not covered
  by the PIO emulator tests and is checked only on hardware.
